# 捷運施工查驗系統 v3

本資料夾（`v3/`）為獨立的雛型版本，可單獨開啟執行；瀏覽器資料庫名稱為 `mrt-qms-v3`。

## v3 調整重點
1. **後台移除「查驗總覽」，首頁改為「停留點會驗管理」**：打開 `admin.html`（或舊連結 `#dashboard`）直接進入停留點會驗管理；原總覽的 KPI、分項工程查驗進度等畫面不再提供。
2. **選單順序調整**：左側選單改為「基本資料 → 查驗作業 → 查詢統計 → 系統」（基本資料與查驗作業對調；查驗總覽移除後，不再有獨立的第一層項目）。
3. **表單範本：分項工程有設定單元時，表單只能掛在單元下**：
   - 「單元」下拉選單移除「（不指定單元，掛在分項工程下）」，預設選第一個單元，新增的範本掛在目前選的單元。
   - 分項工程**新增第一個單元**時，若已有表單掛在分項工程層，會提示並一併移到該單元。
   - 「匯入此分項全部表單」：分項工程已有單元時，表單的「適用單元」不可留白（要填單元編號或「全部」）。
   - 舊資料（分項層的表單）開啟時自動移到該分項工程的第一個單元。
   - 沒有設定單元的分項工程不受影響，表單仍掛在分項工程下。
4. **匯入分項工程的樣本**：標案還沒有分項工程時，下載的樣本與原來相同（標題列＋一列範例）；標案已有分項工程時，樣本直接帶出現有的全部分項工程（項次、名稱、數量、單位、狀態），可改完直接匯入。

# 系統功能總覽（程式閱讀後的整理）

> 本節是閱讀 `v3/` 全部程式（`db.js`、`admin.js`／`admin.html`、`field.js`／`field.html`、`formpdf.js`、`projbase.js`、匯入匯出範本）後整理的功能理解，方便新成員快速掌握系統；後面的「新增／修正紀錄」是各次修改的歷程。

## 1. 系統定位

「捷運施工查驗系統」是捷運工程施工品質**自主檢查（廠商）→ 檢驗停留點會驗／抽查（局工務所）→ 缺失追蹤改善**的雛型，純前端靜態頁（Vue 3 + IndexedDB），分兩個入口：

| 入口 | 使用者 | 裝置 | 用途 |
|---|---|---|---|
| `admin.html` 後台管理 | 系統管理員、局各單位（2J／2B／2F）的管理者 | 桌機 | 標案／分項工程／單元／表單範本設定、會驗排程、查詢統計、帳號參數 |
| `field.html` 現場作業 | 廠商品管人員、捷運局工務所同仁、工務所主任 | 平板／手機（RWD） | 填自主檢查表、申請／執行停留點會驗、抽查紀錄、簽認、缺失改善 |

兩頁共用同一個瀏覽器 IndexedDB（`mrt-qms-v3`），任一頁寫入後以 BroadcastChannel 通知另一頁重新載入；所有「寄 Email／通知主管／憑證簽章」皆為模擬，只留下紀錄。

## 4. 資料模型

層級：**區段標／單一標 → 標案（子標）→ 分項工程 →（單元，選用）→ 表單範本 → 紀錄**。

| 資料（IndexedDB store） | 重點欄位 | 說明 |
|---|---|---|
| `tenders` 標案 | code、parentCode（區段標）、sectionId（部門）、contractor、site、`order` | 由 ProjBase 挑選加入，欄位全由來源帶入；子標順序可拖曳 |
| `subworks` 分項工程 | no（項次）、name、qty、unit、status、order、`unitList` | 項次依 order；`unitList` 為單元編號清單 |
| `templates` 表單範本 | kind（self 自主檢查表／spot 抽查紀錄表）、code 表號、version、status（published／superseded）、`fillMode`（online／pdf）、`unitNo`、`stages`、`items[]`、`pdf`、`pairedSelf` | 線上表單有檢查項目；PDF 範本存空白檔案 |
| 檢查項目 `items[]` | no、key（永久代碼）、stage、name、std 標準、type（option／number／photo／text／linked）、hold ★停留點、photo 必拍、fields[]（label、unit、min、max）、linked 連結表號、ref 引用文件 | 抽查表項目以 `srcKey` 對應自檢項目 |
| `selfChecks` 自主檢查紀錄 | templateId／ver、unit、answers（逐項 judge、values、photos）、hold（各停留點狀態）、linked、recovery、signatures、hash、status（draft／signed）；PDF：fillMode、pdfFile、wfStatus、lockedBy、logs | 一張紀錄綁定表單版本 |
| `requests` 停留點會驗申請 | id `HP-標案-月日-流水號`、scId、itemNo／itemKey、status、scheduledAt、replyDue、shortNotice、inspector、notices[]（通知歷程） | 申請→回覆→會驗 |
| `spotChecks` 抽查紀錄 | kind（hold 會驗／random 隨機）、requestId、scId（廠商自檢對照）、focusNo（本次會驗項目）、answers、calc（單元計價）、signatures；PDF 同上工作流程欄位 | |
| `defects` 缺失追蹤 | id `DF-流水號`、source（自主檢查／自主檢查（停留點）／抽查）、scId／scItemNo、due、status（open 待改善／review 待複查／closed）、fix、history[] | 來源紀錄判 ╳ 自動產生 |
| `docs` 參考文件 | code、name、projKey（區段標／單一標鍵值）、file | 可上傳檔案（20 MB） |
| `users`、`meta` | 帳號；meta 放參數 `params`、流水號 `counter`、已存簽名、seed 旗標 | |

### 系統參數（後台「參數設定」）
停留點須提前申請 24 小時、工務所回覆期限 8 小時、照片壓縮上限 400 KB、缺失改善期限 7 天。

## 5. 核心業務流程

### 5.1 基礎設定（後台）
1. **標案**：「標案與分項工程」→「＋ 新增標案」從標案管理系統（ProjBase）挑選（依目前部門列出區段標＋全部子標、該部門單一標，可搜尋、依階段篩選）；可「移除標案」（已有紀錄者不可，否則連同分項工程、範本一併移除）。標案樹依區段標分組，同區段標內子標可拖曳排序，順序同步套用到所有「標號／分項工程」下拉。
2. **分項工程**：新增、編輯、▲▼ 調整項次、整批匯入（Excel／CSV）、刪除（已有範本或紀錄不可刪）。
3. **單元（選用）**：在「表單範本」頁為分項工程新增單元（如連續壁 P11／P12／P13、基樁 BP-01／BP-02）。**分項工程沒有單元時，表單掛在分項工程層；一旦設定單元，表單只能掛在單元下**（v3 規則）。示範資料：連續壁三單元各有完整一套範本；基樁兩單元。
4. **表單範本**（見 5.2）、**參考文件**（以區段標鍵值管理，範本項目只能引用同鍵值文件）、**帳號**、**參數**。

### 5.2 表單範本（後台「表單範本」）
- 左側：分項工程 → 單元 → 自主檢查表／抽查紀錄表清單（可拖曳排序、刪除；已有紀錄者不可刪）。
- **填寫方式二選一**：
  - **線上表單**：逐項填寫。檢查項目頁籤可設階段（預設施工前／中／後，可自訂如挖掘前／中／後）、項目名稱與標準、判定類型、★停留點、必拍照、引用文件、連結表單（同分項工程其他自主檢查表）、數值欄位（名稱、單位、容許下限／上限，現場輸入時自動建議判定）。另有「表頭與簽認欄」「缺失複查設定」說明頁籤。
  - **空白範本 PDF**：上傳空白 PDF，現場走「下載鎖定→上傳簽名→（廠商簽名）→加簽結案」。含停留點的自主檢查表不可設為 PDF。
- **版本控制**：已有紀錄使用的範本，儲存會另存新版本（舊紀錄保留原版內容與版本號）；項目有永久 `key`，改版、重排後抽查表仍對應正確自檢項目。
- **抽查紀錄表**：可「從自主檢查表同步項目」（帶入階段與 ★），抽查表另有單元計價欄（厚度、長度、計價深度→面積）。
- **匯入／匯出（Excel 統一格式）**：「匯入此分項全部表單」一次建立單元＋表單＋項目＋數值欄位（支援「共用＋單元覆蓋」、整張驗證預覽、同表號更新或另存新版）；單張表單可「匯出 Excel」、「匯入檢查項目」（取代或接在後面）。

### 5.3 自主檢查（現場，廠商）
1. **建立**：「新增自主檢查」依序選 **標號 → 工項 → 單元（有設定單元才出現）→ 表單**；或「掃描單元 QR」（示範以輸入單元代碼模擬），一個單元有多張表時列出選擇。同單元同表號已有填寫中表單會直接開啟；已有簽認完成的需確認「仍要建立」。
2. **填寫**（線上表單）：依階段頁籤（平板左側項目清單＋右側單項、手機為整階段卡片），自動儲存。
   - 開工前確認：掃描單元 QR 確認位置、施工圖核准文號、關聯子表單（表5-4／5-6／5-7…）進度；子表單可直接從主表建立或開啟，簽認後自動帶回。
   - 每項：檢查標準、數值欄位（超出範圍→建議判 ╳）、拍照（自動壓浮水印：時間、標號單元、GPS，並壓縮）、判定 ○合格／╳缺失／╱無此項。
   - **鎖定規則**：前一階段未判完，後一階段鎖定；前面有 ★停留點尚未合格放行，後面所有項目鎖定；連結表單未簽認、必拍照項目沒照片都不能判 ○。
   - **停留點**：判 ○（＋照片）後「申請會驗」；判 ╳ 立即建立缺失追蹤，改善後重新判 ○ 再申請，會驗合格時缺失自動結案。
3. **送出前總覽**：○╳╱ 統計、各停留點放行狀態、自動附件（子表單、照片）；有 ╳ 必選「缺失複查結果」（已完成改善須附照片／未完成另追蹤）。送出條件：全部判定、停留點皆已放行（判 ╱ 者除外）。
4. **簽認**：兩位簽認人依序手寫簽名（現場工程師、工地授權代表，依該標案承包商帳號帶入），勾選「內容不得修改」聲明；簽完產生內容 SHA-256 雜湊、狀態轉「已簽認」並鎖定；判 ╳ 的項目此時建立缺失追蹤。

### 5.4 停留點會驗（後台「停留點會驗」／現場「待辦 > 會驗」「停留點」）
```
廠商申請(pending 待回覆)
  ├─ 距會驗不足 24h：須填原因（系統警示）
  ├─ 工務所 8h 內回覆；逾時→寄提醒 Email 並通知主管（工務所主任）
  ├─ 排定／改期（scheduled 已排定） ─ 或「退回」（rejected，須填原因，廠商可修正後重新申請）
  ├─ 開始會驗（inspecting 檢驗中，建立抽查紀錄；可取消會驗退回已排定）
  └─ 抽查簽認完成 → passed 合格放行（後續項目解鎖）／failed 不合格
```
每個狀態有「通知歷程」時間軸；後台有狀態頁籤、清單／日曆（依日期）檢視。開始會驗時可選抽查紀錄表（預設含本停留點對應項目的線上抽查表，並依單元找該單元的範本）。

### 5.5 抽查紀錄（現場，工務所）
- **兩種來源**：停留點會驗（有「本次會驗項目」，必判定）／隨機抽查（任選項目，至少判一項）。
- 版面與自主檢查表同（階段頁籤、逐項判定、拍照）；數值項目並排顯示「廠商自檢」值與「抽查實測」，超出自動標示。
- 單元計價：厚度、長度、計價深度 → 面積自動計算。
- 未抽查項目簽認時自動填 ╱；簽認人為工務所抽查人員與廠商隨同人員。
- 完成後：判 ╳ 的項目各建缺失追蹤；若為會驗，申請轉為合格放行或不合格，並同步自主檢查表的停留點狀態。

### 5.6 空白範本 PDF 工作流程
狀態：**未開始 → 鎖定中 → 待流轉 →（抽查表）待廠商簽名 → 待主任加簽 → 已結案**，可「解除結案」（會驗抽查除外）。
- 自主檢查表（廠商）：下載並鎖定（首次下載空白範本，之後下載最新版續填）→ 上傳 PDF 並現地手寫簽名 → 待流轉 → 最後上傳者以憑證（模擬：實體自然人憑證／行動自然人憑證 TW FidO）加簽結案。
- 抽查表（工務所）：上傳時選下一關（其他局內人員續填／轉廠商簽名／免廠商簽名逕轉主任）→ 廠商上傳簽名 PDF → 工務所主任加簽結案；若用於會驗，結案合格即放行。
- 鎖定人以外不能上傳；每一步寫入「辦理軌跡」（人員、時間、動作、每版檔案可下載、手寫簽名圖）；現場「待辦 > 表單簽辦」只列輪到目前身分的表單。

### 5.7 缺失追蹤
來源：自主檢查簽認、停留點判 ╳、抽查判 ╳。流程：**待改善**（廠商回報改善：說明＋至少一張照片）→ **待複查**（工務所複查：合格結案／退回須填原因重新改善）→ **已結案**；有改善期限（預設 7 天）與逾期標示，每步記入處理歷程；停留點會驗合格會自動結案同一項缺失。

## 6. 後台各頁功能

| 選單 | 內容 |
|---|---|
